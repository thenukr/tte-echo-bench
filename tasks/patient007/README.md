# tte-echo-bench/patient007

The agent reads a TTE study and fills out a structured report (one JSON per cardiac structure).

| Path | What it is | Who sees it |
| - | - | - |
| `environment/study/` | Study data, copied to `/app/study/`: the clinical context PDF and `Images/` (27 MP4 clips, 39 JPEG stills, `Thumbnails/`). From the patient007 Google Drive folder (`1fUNjryLd5hRcq0plItNitxbJS5077Evu`). | agent |
| `environment/report_template/` | Blank report, copied to `/app/report/`. The agent fills in the `answer` values. | agent |
| `tests/templates/` | Copy of the blank report, used to validate the agent's output | verifier |
| `tests/expert_answers/` | Expert answers from the Tally form, one file per section, keyed by the same field and option slugs. `experts.json` maps `expert_N` to Tally submission ids. | verifier |
| `solution/report/` | Expert-consensus report for harbor's oracle run (pipeline smoke test only) | oracle |

The verifier runs in a separate container. `/app/report` comes back from the agent container through
`artifacts` in `task.toml`. Reward is currently 1 when the report is a complete, valid form: right
files and fields, answers from the allowed options, `only_if` logic followed. Scoring against the
expert answers is not written yet.

## Regenerating

Everything under `report_template/`, `tests/templates/`, `tests/expert_answers/` and
`solution/report/` comes from the Tally form `8NqplO`, generated by `scripts/parse_tally.py`. Save the
raw outputs of the Tally MCP `load_form` and `fetch_submissions` tools as JSON, then run:

```bash
T=tasks/patient007
python3 scripts/parse_tally.py --form form.json --submissions submissions.json \
  --templates-dir $T/environment/report_template --answers-dir $T/tests/expert_answers \
  --solution-dir $T/solution/report
cp $T/environment/report_template/*.json $T/tests/templates/
```

Keep the raw submissions out of git. They contain expert email addresses.
